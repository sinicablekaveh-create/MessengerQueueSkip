# THREE IB | پرونده تحویل به ChatGPT Work و Codex Cloud
تاریخ وضعیت: ۶ نوامبر ۲۰۲۶

## دستور اجرای کار
این پروژه باید در یک گفتگوی جدید **Work** ادامه پیدا کند. گفتگو باید از مستندات این مخزن و فایل‌های پوشه Google Drive شروع کند، کار باقی‌مانده را واقعاً انجام دهد و فقط خروجی‌های ساخته‌شده و آزمایش‌شده را «تمام‌شده» بنامد. پرسش‌های تکراری نپرسد. برای موانع نیازمند ورود یا مجوز کاربر، وضعیت واقعی را ثبت کند.

## آنچه واقعاً تأیید شده
- نسخه اصلی v2.7.0 برای بله، روبیکا و ایتا، با وارد کردن Excel/CSV، سه صف مستقل، متن و عکس، کنترل رابط کاربری Android Accessibility، توقف/ادامه و آزمون پیش‌از‌ارسال در کد موجود است.
- یک گردش‌کار ساخت سه‌پیام‌رسانه در GitHub Actions موفق شده است. این فقط **ساخت و امضای برنامه** را ثابت می‌کند، نه ارسال واقعی.
- اتصال مستقیم تلگرام با TDLib و حساب شخصی، ارسال SMS از سیم‌کارت و WhatsApp Business Cloud API در شاخه main هنوز پیاده‌سازی و تأیید نشده‌اند.
- نسخه‌های جداگانه تلگرام v3.0/v3.1 در گفتگوهای قبلی گزارش شده‌اند؛ **فایل سورس و APK کامل و آزمایش‌شده آن‌ها در بسته سورس فعلی نیست**.
- هنوز هیچ آزمایش دستگاهیِ شش مسیر با رسید ارسال/تحویل تأیید نشده است. هیچ تضمین ۹۹٪/۱۰۰٪ ثبت نکن.

## هدف محصول واحد
شش کانال: Telegram TDLib شخصی، Bale، Rubika، Eitaa، SMS SIM با انتخاب سیم‌کارت و WhatsApp رسمی Business Platform.
قابلیت‌ها: ورود مخاطبان دارای رضایت با Excel/CSV، تیک انتخاب هر کانال، فاصله مستقل ۱ تا ۱۴۴۰ دقیقه، متن و تصویر در کانال‌های پشتیبان، START AUTOMATIC، PAUSE/RESUME، STOP، CLEAR، تست یک مخاطب مجاز، لاگ، مقابله با خطای شبکه و جلوگیری از تکرار ارسال نامشخص.
برای SMS معمولی عکس نفرست؛ SMS فقط متن است. برای WhatsApp خارج از چارچوب رسمی یا به حساب شخصی ارسال انبوه خودکار وعده نده.

## نکات فنی و امنیتی لازم
- برای تلگرام از TDLib واقعی و ورود شماره/OTP/2FA استفاده کن، نه فقط بازکردن کلاینت. API Hash و نشست را در فایل عمومی یا مخزن GitHub منتشر نکن.
- برای WhatsApp از Meta Cloud API با شماره و حساب تجاری تأییدشده، رضایت گیرنده و قالب مجاز و نگهداری توکن در بک‌اند امن استفاده کن.
- برای SMS از SmsManager، subscriptionId انتخابی، مجوز SEND_SMS، پیگیری نتیجه sent/delivery، کنترل هزینه و چندبخشی استفاده کن.
- هر مخاطب باید رضایت دریافت پیام داشته باشد؛ فقط تیک سراسری کافی نیست. ارسال پیام واقعی به شماره‌های آزمایشی فقط با اجازه و آمادگی حساب/دستگاه.
- کد به دو دسته موجود/پیاده‌سازی‌نشده تقسیم شود. هیچ UI نمایشی را «ارسال واقعی» معرفی نکن.

## معیار تحویل نهایی
۱. سورس GitHub در شاخه main + ZIP سورس تمیز با Commit/SHA.
۲. APK قابل نصب با امضای تأیید‌شده، SHA-256 و لینک واقعی.
۳. وضعیت و نتایج تست برای هر شش کانال (تست واقعی، نه فقط Build).
۴. بارگذاری سورس، APK و گزارش به همان پوشه Google Drive.
۵. حفظ محرمانگی تمام کدهای ورود، API Hash، فهرست مخاطبان، توکن‌های Business و کلید امضا.
۶. اگر هر کانال به اکانت، تأیید هویت، توکن یا مجوز سیستم نیاز دارد، آن وابستگی صریحاً اعلام شود و تا فراهم شدن آن کانال آماده فرض نشود.

## وضعیت اشتراک پوشه Drive
در بررسی قبلی پوشه Theree iba خصوصی و فقط متعلق به مالک بود؛ در ابزار موجود دسترسی «Anyone with link / Editor» برای پوشه قابل اعمال نبود. اعطای این دسترسی **تأیید نشده** است. هنگام تغییر دستی، ابتدا مطمئن شو در پوشه هیچ رمز یا مخاطب خصوصی وجود ندارد؛ ویرایشگر عمومی می‌تواند فایل‌ها را عوض کند. بهتر است برای کاربران عمومی Reader و برای توسعه‌دهندگان مشخص Editor تنظیم شود.

## متن آماده برای نخستین پیام در Work
پروژه THREE IB را بدون پرسیدن سؤال‌های تکراری بر اساس مخزن GitHub و پوشه Google Drive ادامه بده. ابتدا AGENTS.md و docs/WORK_HANDOFF_FA.md را در مخزن بخوان؛ شاخه main را با شاخه three-ib-apk-v1 مقایسه کن. هدف نهایی APK واقعی شش‌کاناله تلگرام شخصی با TDLib، روبیکا، بله، ایتا، SMS SIM و WhatsApp Business API رسمی است. صف Excel با رضایت سطری، متن/عکس، فاصله مستقل، START AUTOMATIC، توقف/ادامه، تست، لاگ و جلوگیری از ارسال تکراری را تکمیل کن. کامپایل و امضا را با CI تأیید کن، سورس و APK و گزارش تست را به پوشه Theree iba در Google Drive منتقل کن، و کانال‌های آزمایش‌نشده را موفق معرفی نکن. API_HASH یا اطلاعات حساب و مخاطبان نباید عمومی شوند. از مجوزهای فعلی اتصال GitHub و Google Drive استفاده کن. اگر ورود/توکنِ حساب ثالث یا مجوز اندروید موردنیاز باشد، مراحل دستگاه‌محور را جداگانه و صادقانه ثبت کن.

## دستور جدید تکمیل برای Work (۶ نوامبر ۲۰۲۶)
سند اجرایی تازه‌ای در همان پوشه Google Drive ساخته و خوانده‌شدن و محل آن بررسی شده است:
https://docs.google.com/document/d/1ByDuRXKO2uX92GE58ISNVCajn0u5UAFxtypTJUPmVSA/edit
در گفتگوی جدید ChatGPT Work ابتدا سند فوق و AGENTS.md را بخوان، سپس کارهای فنی و تحویل نهایی را طبق معیارهای آن انجام بده. در Codex Cloud همین مخزن main و راهنمای AGENTS.md مرجع هستند.

کاربر برای اجرای مراحل فنی در حساب‌های متصل، ایجاد شاخه/PR و Build/Sign/Verify و آپلود خروجی‌ها به پوشه Theree iba مجوز داده و تأکید کرده سؤال‌های تکراری نپرس. مجوز کاربر جایگزین مجوز Android، ورود OTP، تأیید حساب WhatsApp Business یا دریافت توکن در مسیر امن نیست.

کاربر درخواست اشتراک پوشه با «Anyone with the link / Editor» داده، ولی در بازبینی این سند هنوز پوشه خصوصی بوده است؛ بنابراین **ادعای فعال‌کردن دسترسی عمومی نکن**. اگر Work Cloud Browser و دسترسی واقعی UI موجود بود، پس از بررسی دقیق پوشه برای وجود داده شخصی و اطلاعات محرمانه، اشتراک‌گذاری را انجام بده و با Drive metadata تأیید کن. عمومی‌کردن دسترسی ویرایش به همه دارندگان لینک، خطر جایگزینی APK/سورس را ایجاد می‌کند؛ هش نسخه و مشخصات امضای نهایی را ثبت کن.

فایل‌های موجود در Google Drive صرفاً نسخه پایه هستند؛ APK شش‌مسیره و نتیجه تست واقعی هر شش مسیر همچنان تحویل نشده است. اجرای موفق GitHub Actions روی نسخه پایه به معنای موفقیت ارسال نیست.
